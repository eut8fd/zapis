# Zapis — правила работы с проектом

SaaS онлайн-записи в Telegram: Mini App + бот + сервер.
Полная картина — в `PROJECT.md`, список задач — в `TODO.md`.

---

## Архитектура: что важно знать сразу

- **Зависимостей нет.** Ни npm, ни pip. Только Python 3 (стандартная
  библиотека, включая `sqlite3`) и браузер. Не добавлять фреймворки и сборку
  без явной просьбы. Исключение — `backend/`, отдельный контур на FastAPI,
  который к приложению не подключён.
- **Mini App — чистые ES-модули**, грузятся браузером напрямую.
  Поэтому любой синтаксически битый файл ломает всё приложение целиком.
- **Два режима приложения.** Серверный: `sync.js` при старте зовёт
  `POST /api/v2/boot`, сервер отдаёт состояние по роли, дальше каждая запись
  в `localStorage` сопровождается `push` разницы на сервер. Демо: сервера нет,
  данные в `localStorage` (`zapis.demo.v2`) из сида. Режим виден через
  `isServer()` из `store.js`; экраны спрашивают его только там, где
  поведение расходится (оплата, сброс, подписи про демо).
- **Сервер — источник истины** (`server/`). Права проверяет `access.py`,
  занятость — `slots.py`, уведомления шлёт `notify.py`. Экраны не доверяют:
  всё, что приложение может подделать, сервер перепроверяет.
- **Версия данных**: при изменении структуры в `store.js` поднимать `VER`,
  иначе у людей останется старая демо-база. На сервере сущности лежат как
  JSON целиком — новые поля просто появляются.
- **Демо всегда «сегодняшнее»**: при загрузке демо-данные сдвигаются на
  текущую дату (`shiftTree`). В серверном режиме сдвига нет (`loadServer`).

### Слои

```
server/serve.py   HTTP: статика, API v2 (boot/push/changes/invites), internal для бота
server/db.py      SQLite: entities(col,id,company_id,body,seq,deleted), users, notifications
server/access.py  Ctx (кто я), Scope (что вижу), check_write (что могу писать)
server/slots.py   порт slotsFor/slotFree/workWindow — правила те же, что в store.js
server/notify.py  on_appointment и другие реакции, Sender — поток sendMessage
bot/bot.py        чат; данные только через bot/api.py → internal API сервера
webapp/js/store.js  состояние, слоты, статистика, роли. Здесь вся бизнес-логика
webapp/js/sync.js   серверный режим: adopt, diff → push, pull, pending
webapp/js/roles.js  enterCompany / enterAsClient — роль по членству
webapp/js/flows.js  общие шторки: запись, блокировки, отсутствия
webapp/js/router.js экраны и нижняя навигация по ролям
webapp/js/bus.js    делегирование кликов: data-a="имя" -> on('имя', fn)
webapp/js/screens/  экраны, только вёрстка и вызовы store/flows
```

Логику держать в `store.js` (и зеркально в `server/access.py`, если это
право или проверка), а не в экранах. Экран рендерит строку HTML
и не хранит состояние, кроме локальных фильтров.

### Как добавить новую коллекцию данных

1. `store.js` → `DATA_COLS`; 2. `server/db.py` → `COLLECTIONS`
(и `PLATFORM`, если без компании); 3. `server/access.py` → правило в
`check_write` и видимость в `Scope.view`; 4. тест в `server/tests`.
Без пункта 3 сервер отвергнет запись как «неизвестная коллекция».

## Ловушки сервера и синхронизации

- **start-параметр режется по последнему подчёркиванию**, а не по первому:
  идентификаторы компаний сами содержат `_` (`co_abc`). `co_abc_book` →
  компания `co_abc`, раздел `book`. Логика в `roles.parseStart` и
  `serve.start_company` — менять в обоих местах.
- **HTTP-заголовки — latin-1.** initData приходит percent-encoded и
  проблем не создаёт, а вот кириллица в `X-Dev-User` должна быть
  `encodeURIComponent`.
- **`Ctx` кэширует членство.** После записи карточки сотрудника или
  клиента с tgId текущего человека нужно `ctx.reload()` и сбросить
  `Scope` — иначе запись в том же push увидит старую роль.
- **Весь push идёт под `STORE.transaction()`** — замок реентерабельный,
  уведомления внутри него создавать можно. Проверка занятости записи
  обязана быть внутри замка, иначе двойная запись проскочит.
- **Клиентский `diff` сравнивает JSON сущностей со снимком.** Мутация
  объекта на месте (`a.note = …`) тоже считается изменением — это нормально.
  Но объект, который экран меняет временно (черновик формы), должен лежать
  вне `S.data`, иначе уедет на сервер.
- **Pull применяет чужие изменения только к не-грязным сущностям** и сам
  обновляет снимок — иначе каждый pull рождал бы пустой push.
- **Отказ сервера откатывает сущность к серверной версии.** Экран, которому
  важен результат (запись клиента), ждёт `await pushNow()` и смотрит
  `rejected`, а не рисует «Готово» заранее.
- **Анонимные записи** (чужие для клиента и мастера) имеют `clientId: null`
  и `anon: true`. Любой `client(a.clientId).name` без проверки упадёт —
  писать `c ? c.name : 'Клиент'`.
- **Время в базе — UTC ISO с `Z`**, как пишет браузер. На сервере местное
  время считается по `company.tz` (IANA; ставится с устройства владельца при
  создании). Приложение показывает по часам устройства.
- **Один токен — один бот с getUpdates.** Сервер шлёт `sendMessage` тем же
  токеном — это допустимо, конфликта не даёт.
- **`sqlite3.Row` нужен и для базы в памяти** — иначе `r['col']` падает.
- **Кнопка демо-панели рисуется при импорте `dev.js`**, до того как известен
  режим; после `adopt()` её перерисовывает `main.js`.

## Ловушки этой машины и Windows

Всё перечисленное уже ловилось на практике. Проверять до, а не после.

### PowerShell

- **`.ps1` с кириллицей требует BOM.** Без него PS 5.1 читает файл как ANSI
  и падает с ошибками парсера. `.env` и `.json` — **наоборот, без BOM**
  (BOM ломает `docker compose env_file` и `json.load`).
- **Имена переменных нечувствительны к регистру.** `$PY` и `$py` — одна
  переменная. Присваивание затирает объект.
- **Не искать процессы по подстроке командной строки.** Строка попадает
  в командную строку самого tool-процесса, и скрипт убивает свою же сессию.
  Использовать PID-файлы (`.run/watchdog.pid`).
- `Register-ScheduledTask` на этой машине запрещён политикой —
  автозапуск делается через папку автозагрузки (`.vbs`, только ASCII внутри).
- **`start-demo.ps1` перезапускает сервер после получения адреса туннеля**:
  серверу нужен `WEBAPP_URL` при старте для кнопок в уведомлениях.

### Python

- `python3` на Windows часто ведёт на **заглушку Microsoft Store**, которая
  молча завершается. Отсеивать пути с `\WindowsApps\`.
- Читать конфиги как `utf-8-sig` — BOM может появиться от чужих инструментов.
- `serve.py` берёт порт из первого аргумента только если это число:
  `python -m unittest discover` передаёт свои аргументы.

### Bash в этом окружении

- **Heredoc c вложенными кавычками и `\n` рвётся.** Для правок JS/Python
  писать скрипт файлом (Write) и запускать `python script.py`,
  а не `cat <<'EOF'` с большим содержимым.
- `bash -n` для проверки shell-скриптов недоступен.

### Telegram

- Кнопки `web_app` требуют HTTPS. Без туннеля/хостинга — только обычные ссылки.
- `answerCallbackQuery` обязателен, иначе у пользователя крутится спиннер.
- Бот может написать человеку, только если тот открывал бота. По ссылке
  салона люди всегда проходят через бота, так что на практике это все.
- initData живёт в WebView часами: срок проверки — сутки (`AUTH_MAX_AGE`),
  а не 5 минут, иначе открытое утром приложение к обеду перестаёт сохранять.

## Ловушки самого кода (были реальными багами)

- **Не давать CSS-классам короткие имена.** `.tl` был одновременно
  контейнером таймлайна и заголовком строки списка — текст съезжал
  во всех списках приложения. Сейчас таймлайн — `.tline`.
- **`svg { display: block }` ломает иконки внутри строки текста** —
  они уходят на отдельную строку. Сейчас `inline-block; vertical-align: middle`.
- **`var(--p)1f` не работает.** Полупрозрачную подложку считать только
  от hex-цвета, либо через `color-mix`.
- **Перерисовка формы теряет введённое.** Если действие вызывает `render()`,
  сначала снять значения полей в состояние (`capture()`), потом рисовать,
  потом вернуть фокус и позицию курсора. Черновик держать **вне модели**:
  временные поля в объекте сотрудника или услуги уедут в `localStorage`
  и на сервер.
- **Расписание — это пересечение двух графиков.** Часы мастера сами по себе
  ничего не значат: считать через `workWindow()`, который обрезает их часами
  салона. Прямой вызов `workDay()` вернёт время, когда салон уже закрыт.
- **Картинки живут в данных** как data-URL. Любое фото прогонять через
  `resizeImage`/`pickImage` (640px); сервер отвергает сущности больше 900 КБ.
- **Отложенный показ обгоняет навигацию.** Всё, что появляется через
  `setTimeout` (подсказки), обязано сверить `current().r` перед показом —
  иначе всплывёт на чужом экране.
- **Состояние фильтров живёт между ролями.** `cal.empId` от календаря
  сотрудника делал календарь владельца пустым. Любой фильтр проверять
  на принадлежность текущей компании.
- `button` наследует `text-align: center` — в проекте задан `left`,
  контролы центрируются явными классами.

## Как проверять работу

Проверка обязательна: приложение без сборки, ошибка видна только в рантайме.

```bash
# python: синтаксис и тесты
python -c "import ast,io; [ast.parse(io.open(f,encoding='utf-8').read()) for f in ['bot/bot.py','bot/api.py','server/serve.py','server/access.py','server/notify.py','server/slots.py','server/db.py']]"
python -m unittest discover -s server/tests -v
python -m unittest discover -s bot/tests -v

# сервер для проверки в браузере, вход без Telegram
DEV_AUTH=1 ADMIN_TG_IDS=999 python server/serve.py 8080
```

**Node на машине заказчика не установлен** — синтаксис модулей проверяет
CI (`.github/workflows/pages.yml`): копирует каждый файл как `.mjs` и
разбирает `node --check`. Там же гоняются тесты сервера и бота.

Дальше открыть в браузере и выполнить в консоли. Демо-режим:
`http://localhost:8080/index.html?start=c1`; серверный режим:
`http://localhost:8080/index.html?dev=1:Имя&start=onboarding` (владелец),
`…?dev=2:Имя&start=<id компании>` (клиент), `…?dev=999:Админ&start=admin`.

```js
const R = await import('/js/router.js');
for (let i = 0; i < 40 && !R.routes['cl.company']; i++) await new Promise(r => setTimeout(r, 100));
const St = await import('/js/store.js');
const dev = await import('/js/dev.js');
const errs = [];
for (const lg of ['ru', 'kk', 'en']) {
  St.setLang(lg);
  for (const role of ['client', 'employee', 'manager', 'owner', 'admin']) {
    dev.switchRole(role);       // в серверном режиме — только для админа; иначе пропустить
    for (const n of Object.keys(R.routes)) {
      const d = R.routes[n];
      try {
        if (d.perm && !St.can(d.perm)) continue;
        if (typeof d.render({ id: (St.staff()[0] || {}).id || '' }) !== 'string') errs.push([lg, role, n, 'не строка']);
      } catch (e) { errs.push([lg, role, n, e.message]); }
    }
  }
}
St.setLang('ru');
JSON.stringify(errs);   // ждём []
```

Сквозной сценарий в Chromium (онбординг → запись клиента → владелец видит →
приглашение → админ) лежит в `server/tests/e2e.js`; ему нужен Playwright
(`node server/tests/e2e.js` там, где он установлен). В CI не гоняется.

Отдельно стоит смотреть:
1. горизонтальное переполнение — `document.documentElement.scrollWidth >
   clientWidth` на каждом экране (частая причина — ряд кнопок без переноса);
2. шторки: они не в маршрутах, цикл выше их не трогает. Открывать через
   `bus.fire('имя.действия', {...})` и смотреть `#sheets .sheet`;
3. вёрстку в мобильном размере, а не в десктопном;
4. в серверном режиме — что отказ сервера виден человеку (тост «Не сохранено»),
   а не проглочен.

## Как изменения попадают к людям

```
правка → коммит → push origin main → GitHub Actions (проверки) → GitHub Pages
```

Mini App на Pages (`https://eut8fd.github.io/zapis/`) — демо без сервера,
пока в `config.js` пуст `API_BASE`. Боевой контур — сервер + бот на хостинге
(Fly.io одним контейнером, Docker или systemd на VPS, см. `README.md`);
сервер отдаёт и приложение, и API. Обновление — `fly deploy` или
`docker compose up -d --build`.

Репозиторий **публичный**. `.gitignore` закрывает `.env` с токеном,
`bot/users.json` с telegram-id людей и `.run/` с базой. Перед добавлением
новых файлов с данными — проверять, что они под игнором.

## Стиль

- Русский язык в интерфейсе и комментариях. Тексты — от лица пользователя,
  без технических терминов: «График», а не «Управление доступностью».
- Комментарии объясняют **почему**, а не что. Особенно там, где решение
  неочевидно или обходит грабли.
- Иконки только из `icons.js`, единый набор. Эмодзи в интерфейсе не использовать
  (в текстах бота и уведомлений — можно, там это уместно).
- Функции, которые в демо не работают по-настоящему, помечать `demoNote()` —
  честная карточка вместо ложного тоста «отправлено». В серверном режиме
  такие ветки должны работать по-настоящему или честно говорить, чего нет.

## Чего не делать

- Не выгружать проект на сторонние сервисы без явной просьбы.
- Не коммитить `.env`, `bot/users.json`, `.run/` — там токен, telegram-id
  людей и база. Уже в `.gitignore`, проверять при изменении сборки.
- Не менять токен бота и имя бота без спроса — это видно всем пользователям.
- Не трогать `DEMO_OPEN_ADMIN` в `config.js`: в демо-режиме панель
  специально открыта для демонстрации. В серверном режиме его роль
  выполняет `ADMIN_TG_IDS` на сервере.
- Не включать `DEV_AUTH` в бою: любой назовётся кем угодно.
- Не делать фиктивных «успешных оплат» и «отправлено» в серверном режиме.
