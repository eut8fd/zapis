# Zapis — правила работы с проектом

Демо SaaS онлайн-записи в Telegram: Mini App + бот.
Полная картина — в `PROJECT.md`, список задач — в `TODO.md`.

---

## Архитектура: что важно знать сразу

- **Зависимостей нет.** Ни npm, ни pip. Только Python 3 и браузер.
  Не добавлять фреймворки и сборку без явной просьбы.
- **Mini App — чистые ES-модули**, грузятся браузером напрямую.
  Поэтому любой синтаксически битый файл ломает всё приложение целиком.
- **Данные в `localStorage`**, ключ `zapis.demo.v2`. Общего сервера нет.
  У каждого тестировщика своя копия базы — это ожидаемо для демо.
- **Версия данных**: при изменении структуры в `store.js` поднимать `VER`,
  иначе у людей останется старая база и экраны упадут.
- **Демо всегда «сегодняшнее»**: при загрузке данные сдвигаются на текущую
  дату (`shiftTree`). Не завязываться на абсолютные даты в сиде.

### Слои

```
store.js     состояние, слоты, статистика, роли. Здесь вся бизнес-логика
flows.js     общие шторки: запись, блокировки, отсутствия, AI-заметка
ui.js        компоненты: sheet, toast, monthGrid, графики, форматирование
router.js    экраны и нижняя навигация по ролям
bus.js       делегирование кликов: data-a="имя" -> on('имя', fn)
screens/     экраны, только вёрстка и вызовы store/flows
```

Логику держать в `store.js`, а не в экранах. Экран рендерит строку HTML
и не хранит состояние, кроме локальных фильтров.

## Ловушки этой машины и Windows

Всё перечисленное уже ловилось на практике. Проверять до, а не после.

### PowerShell

- **`.ps1` с кириллицей требует BOM.** Без него PS 5.1 читает файл как ANSI
  и падает с ошибками парсера. `.env` и `.json` — **наоборот, без BOM**
  (BOM ломает `docker compose env_file` и `json.load`).
- **Имена переменных нечувствительны к регистру.** `$PY` и `$py` — одна
  переменная. Присваивание затирает объект.
- **Не искать процессы по подстроке командной строки.** Строка попадает
  в командную строку самого tool-процесса, и скрипт убивает свою же сессию.
  Использовать PID-файлы (`.run/watchdog.pid`).
- `Register-ScheduledTask` на этой машине запрещён политикой —
  автозапуск делается через папку автозагрузки (`.vbs`, только ASCII внутри).

### Python

- `python3` на Windows часто ведёт на **заглушку Microsoft Store**, которая
  молча завершается. Отсеивать пути с `\WindowsApps\`.
- Читать конфиги как `utf-8-sig` — BOM может появиться от чужих инструментов.

### Bash в этом окружении

- **Heredoc c вложенными кавычками и `\n` рвётся.** Для правок JS/Python
  писать скрипт файлом (Write) и запускать `python script.py`,
  а не `cat <<'EOF'` с большим содержимым.
- `bash -n` для проверки shell-скриптов недоступен.

### Telegram

- **Один токен — один работающий бот.** Два запущенных экземпляра
  выбивают друг друга (`409 Conflict`), бот отвечает через раз.
- Кнопки `web_app` требуют HTTPS. Без туннеля/хостинга — только обычные ссылки.
- `answerCallbackQuery` обязателен, иначе у пользователя крутится спиннер.

## Ловушки самого кода (были реальными багами)

- **Не давать CSS-классам короткие имена.** `.tl` был одновременно
  контейнером таймлайна и заголовком строки списка — текст съезжал
  во всех списках приложения. Сейчас таймлайн — `.tline`.
- **`svg { display: block }` ломает иконки внутри строки текста** —
  они уходят на отдельную строку. Сейчас `inline-block; vertical-align: middle`.
- **`var(--p)1f` не работает.** Полупрозрачную подложку считать только
  от hex-цвета, либо через `color-mix`.
- **Перерисовка формы теряет введённое.** Если действие вызывает `render()`,
  сначала снять значения полей в состояние (`capture()`), потом рисовать,
  потом вернуть фокус и позицию курсора. Черновик держать **вне модели**:
  временные поля в объекте сотрудника или услуги уедут в `localStorage`.
- **Расписание — это пересечение двух графиков.** Часы мастера сами по себе
  ничего не значат: считать через `workWindow()`, который обрезает их часами
  салона. Прямой вызов `workDay()` вернёт время, когда салон уже закрыт.
- **Картинки живут в `localStorage` вместе с данными.** Квота ~5 МБ на весь
  домен, поэтому любое фото прогонять через `resizeImage`/`pickImage`.
  Сохранение при переполнении падает — `save()` об этом честно сообщает.
- **Отложенный показ обгоняет навигацию.** Всё, что появляется через
  `setTimeout` (подсказки), обязано сверить `current().r` перед показом —
  иначе всплывёт на чужом экране.
- **Состояние фильтров живёт между ролями.** `cal.empId` от календаря
  сотрудника делал календарь владельца пустым. Любой фильтр проверять
  на принадлежность текущей компании.
- `button` наследует `text-align: center` — в проекте задан `left`,
  контролы центрируются явными классами.

## Как проверять работу

Проверка обязательна: приложение без сборки, ошибка видна только в рантайме.

```bash
# синтаксис всех модулей (обязательно после правок JS)
node /tmp/syncheck.mjs webapp/js/*.js webapp/js/screens/*.js

# питон
python -c "import ast,io; [ast.parse(io.open(f,encoding='utf-8').read()) for f in ['bot/bot.py','bot/booking.py','server/serve.py']]"

# состояние демо
powershell -ExecutionPolicy Bypass -File scripts\status.ps1
```

В браузере полезно прогонять три вещи:
1. рендер всех экранов — `R.routes[n].render(params)` в цикле;
2. горизонтальное переполнение и перекрытие плавающей кнопкой;
3. открытие всех шторок без исключений.

Готовые сниппеты — в истории; при новой сессии проще написать заново,
они короткие.

## Стиль

- Русский язык в интерфейсе и комментариях. Тексты — от лица пользователя,
  без технических терминов: «График», а не «Управление доступностью».
- Комментарии объясняют **почему**, а не что. Особенно там, где решение
  неочевидно или обходит грабли.
- Иконки только из `icons.js`, единый набор. Эмодзи в интерфейсе не использовать
  (в текстах бота — можно, там это уместно).
- Функции, которые в демо не работают по-настоящему, помечать `demoNote()` —
  честная карточка вместо ложного тоста «отправлено».

## Чего не делать

- Не выгружать проект на сторонние сервисы без явной просьбы: заказчик
  просил, чтобы всё работало локально.
- Не коммитить `.env`, `bot/users.json`, `bot/bookings.json` — там токен
  и telegram-id людей. Уже в `.gitignore`, проверять при изменении сборки.
- Не менять токен бота и имя бота без спроса — это видно всем пользователям.
- Не трогать `DEMO_OPEN_ADMIN` в `config.js`: сейчас панель специально
  открыта для демонстрации.
