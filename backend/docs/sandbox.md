# Локальная песочница

Контур для ручной проверки production-backend без Telegram и без демо-данных.
Демо-бот, демо-сервер и `localStorage`-приложение здесь не участвуют: у
песочницы своя база, свой порт и свой процесс. Их можно держать запущенными
одновременно.

```bash
powershell -ExecutionPolicy Bypass -File scripts\sandbox.ps1
```

Консоль откроется сама: <http://localhost:8000/sandbox/>

```bash
powershell -ExecutionPolicy Bypass -File scripts\sandbox.ps1 -Stop
```

```bash
powershell -ExecutionPolicy Bypass -File scripts\sandbox.ps1 -Fresh
```

`-Fresh` удаляет базу и историю сообщений — начинаете с нуля.

---

## Что подменено, а что настоящее

Подменены ровно две вещи, обе на границе с внешним миром:

| Что | В бою | В песочнице |
|---|---|---|
| Кто ты | подпись Telegram `initData` | имя в форме входа |
| Куда уходит сообщение | Telegram Bot API | файл `.run/sandbox-inbox.jsonl`, видно на вкладке «Уведомления» |

Всё остальное — то же самое: те же таблицы и миграции, та же выдача
сессий с ротацией refresh, те же права из membership, тот же slot engine,
та же очередь уведомлений с повторами, backoff и отменой устаревших задач.
Если сценарий прошёл здесь, он прошёл на настоящем коде.

**Одно имя — один человек.** Telegram ID выводится из имени, поэтому
повторный вход тем же именем возвращает того же пользователя с его
записями. Разные имена — разные люди.

## Почему это не дыра в production

Оба режима включаются флагами `DEV_AUTH_ENABLED` и `NOTIFY_TRANSPORT=local`.
Конфигурация (`app/config.py`) не даёт запустить с ними ничего, кроме
`APP_ENV=local`: staging и production падают на старте с явной ошибкой,
а не поднимаются с открытой дверью. Маршруты `/api/v1/dev/*` и статика
консоли вообще не регистрируются без флага, и каждый обработчик проверяет
его ещё раз.

## Порядок проверки

**1. Люди.** Войдите именем владельца, например «Айгуль Салонова».

**2. Бизнес.** Создайте компанию — она, филиал и membership владельца
создаются одной транзакцией. Дальше по порядку:

- услуга: название, цена, длительность, уборка после клиента;
- мастер: он автоматически привязывается к существующим услугам, кнопка
  «все услуги» перепривязывает вручную. Мастер без привязки к услуге в
  выдачу слотов не попадёт — это не баг, а требование ТЗ (SVC-004);
- график филиала: часы мастера считаются пересечением с этими часами;
- правила записи;
- «Проверить готовность» и «Опубликовать». Пока не опубликована —
  снаружи компании не существует.

**3. Люди.** Войдите вторым именем. Это клиент, членства в компании у
него нет и не появится.

**4. Клиент.** Каталог → «записаться» → услуга, мастер, дата → время.
Слот занимается атомарно: если между показом и нажатием время займут,
придёт понятная ошибка с альтернативами, а не молчаливый успех.

**5. Уведомления.** Подтверждение приходит сразу. Напоминания — в
запланированное время; очередь под ними показывает, когда сработают.

**6. Бизнес → Календарь.** Завершите визит. Через два часа после
завершения уйдёт запрос отзыва — событие ставится в outbox с задержкой,
поэтому в коротком тесте его не видно; в очереди оно появится.

## Как проверить напоминания за пару минут

Ждать сутки не нужно. На вкладке «Бизнес» → «Правила записи»:

- **Напоминания за, мин** — `3, 1`;
- **Мин. время до записи** — `0`, иначе ближайшие слоты закрыты;
- **Шаг сетки** — `5`, иначе ближайший слот может быть через полчаса.

Если сейчас ночь, а график салона с 10:00 — свободного времени не будет.
Поставьте часы `00:00–23:59` на все дни, это ровно то, что делает
настоящий круглосуточный салон.

Дальше запишитесь на слот минут через пять и смотрите «Уведомления».
Проверено: подтверждение приходит в секунду записи, напоминания —
за 3 и за 1 минуту до визита.

## Что здесь не работает

Не потому что песочница урезана, а потому что этого пока нет в backend:

- **оплаты** — провайдер не выбран, фиктивных «успешных оплат» в коде нет;
- **рассылки, аналитика, экспорт, медиафайлы** — модели заведены,
  реализации нет;
- **сообщения мастеру** приходят, только если за карточкой мастера стоит
  живой человек. Чтобы проверить: в команде нажмите «пригласить», токен
  вставьте на вкладке «Люди» под другим именем. Это настоящий поток приглашения
  из ТЗ, с одноразовым токеном и хэшем в базе.
