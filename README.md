# Zapis — онлайн-запись в Telegram

Mini App + бот + сервер. Клиент записывается по ссылке салона, владелец
видит запись у себя сразу, бот напоминает о визите. Зависимостей нет:
только Python 3 и браузер.

---

## Как это устроено

```
server/serve.py   сервер: база SQLite, API, статика Mini App, уведомления в Telegram
bot/bot.py        бот: меню, запись прямо в чате, кабинет — всё через сервер
webapp/           Mini App: чистые ES-модули, без сборки
```

Один и тот же Mini App работает в двух режимах:

* **серверный** — приложение открыто из Telegram и сервер отвечает: данные
  живут на сервере, роль человека определяется по его telegram-id, записи
  видны всем участникам сразу, уведомления уходят по-настоящему;
* **демо** — сервера нет (GitHub Pages без `API_BASE`, файл с диска):
  данные в `localStorage`, демо-компании из сида, переключение ролей
  в демо-панели. Так проект показывают без инфраструктуры.

Кто есть кто, решает сервер по данным: карточка сотрудника с вашим
telegram-id — вы в команде (владелец или мастер), открыли ссылку салона —
вы его клиент, id в `ADMIN_TG_IDS` — администратор платформы. Один человек
может быть владельцем одного салона и клиентом другого.

## Быстрый старт (локально)

1. Создайте бота у @BotFather, скопируйте токен.
2. `cp .env.example .env`, заполните `BOT_TOKEN` и `ADMIN_TG_IDS` (ваш Telegram ID
   покажет команда `/admin` в боте).
3. Запустите:

```bash
python server/serve.py 8080      # сервер
python bot/bot.py                # бот (в другом окне)
```

Telegram открывает Mini App только по https, поэтому для проверки из
телефона нужен туннель. На Windows всё делает один скрипт:

```bash
powershell -ExecutionPolicy Bypass -File scripts\start-demo.ps1
```

Он поднимает сервер, открывает https-туннель Cloudflare, записывает адрес
в `.env` как `WEBAPP_URL`, перезапускает сервер с этим адресом и стартует
бота. Дальше в Telegram: **ваш бот → /start → «Создать бизнес»**.

Проверить в обычном браузере без Telegram можно с `DEV_AUTH=true` в `.env`:
адрес `http://localhost:8080/?dev=1:Имя&start=onboarding` откроет приложение
от имени тестового пользователя с id 1. В бою `DEV_AUTH` обязан быть выключен.

## Что происходит после запуска

**Владелец** открывает бота → «Создать бизнес» → три шага онбординга
(название, часы, первая услуга) → кабинет. В настройках дозаполняет адрес
и телефон, в «Команде» делает ссылку-приглашение мастеру. Ссылка для
клиентов: `t.me/<бот>?start=<id компании>` — она в «Ещё» → «Поделиться».

**Клиент** открывает ссылку → страница салона → услуга → мастер → дата →
время. Запись появляется у владельца и мастера мгновенно (приложение
подтягивает изменения раз в полминуты и при возвращении на экран), в чат
владельцу приходит «Новая запись». Записаться можно и не открывая
приложение — «Быстрая запись в чате».

**Уведомления** шлёт сервер от имени бота:

| кому | что |
|---|---|
| клиенту | подтверждение (если записал салон), за 24 часа, за 2 часа, просьба об отзыве после визита, отмена и перенос салоном |
| владельцу и мастеру | новая запись, отмена и перенос клиентом, сотрудник вошёл по приглашению, утренняя сводка (если включена) |
| владельцу | подписка продлена, подписка заканчивается через три дня |
| администратору | новая компания, заявка на оплату, жалоба или обращение |

Какие напоминания слать, владелец выбирает в «Настройки → Напоминания»;
там же — тестовое сообщение себе.

**Подписка.** Новая компания получает 14 дней пробного периода (`TRIAL_DAYS`).
Платёжного провайдера нет, и фиктивной оплаты тоже нет: владелец нажимает
«Продлить подписку», администратор получает заявку в Telegram и после
оплаты продлевает срок в панели Super Admin. Реквизиты для `PAYMENT_NOTE`
в `.env` владелец видит прямо в разделе «Подписка». После окончания срока
плюс `GRACE_DAYS` страница записи перестаёт принимать новых клиентов.

**Рассылки** из кабинета и из панели платформы уходят по-настоящему — тем
клиентам и владельцам, кто открывал бота.

**Без сети** приложение открывается на последних данных с сервера: правки
копятся и уходят, когда связь вернётся. Записи при этом сервер всё равно
проверит на занятость — чужое время занять не получится.

## Публикация

### Вариант A. Fly.io — один контейнер, бот и сервер вместе

```bash
fly auth login
fly launch --no-deploy --copy-config
fly volumes create zapis_data -s 1
fly secrets set BOT_TOKEN=... ADMIN_TG_IDS=123456789 WEBAPP_URL=https://<app>.fly.dev
fly deploy
```

`fly.toml` уже настроен: `deploy/run.py` поднимает сервер и бота одним
процессом, база лежит на томе `/data`. Mini App отдаётся самим сервером,
поэтому `WEBAPP_URL` — адрес приложения на Fly. Если приложение хотите
держать на GitHub Pages, впишите адрес сервера в `API_BASE`
(`webapp/js/config.js`) и укажите `WEBAPP_URL` страниц.

### Вариант B. Свой сервер с доменом (Docker)

```bash
git clone <репозиторий> /opt/zapis && cd /opt/zapis
cp .env.example .env && nano .env   # BOT_TOKEN, DOMAIN, WEBAPP_URL=https://DOMAIN, ADMIN_TG_IDS
docker compose up -d
```

Три сервиса: сервер, бот и Caddy с автоматическим HTTPS. База и токен
бота к серверу лежат на общем томе `app-data`; если бот и сервер стоят
на разных машинах, задайте `INTERNAL_TOKEN` в `.env` обоим.

Без Docker — юниты systemd в `deploy/` (`zapis-web.service`,
`zapis-bot.service`), данные в `/var/lib/zapis`.

### Mini App на GitHub Pages

Папка `webapp/` публикуется на Pages при каждом пуше в `main`
(`.github/workflows/pages.yml`), перед публикацией прогоняются проверка
синтаксиса модулей и тесты сервера и бота. Без `API_BASE` это демо на
`localStorage`; с `API_BASE` — настоящий клиент вашего сервера.

## Переменные окружения

Полный список с комментариями — в `.env.example`. Главное:

| переменная | зачем |
|---|---|
| `BOT_TOKEN` | токен бота; сервер проверяет им подпись Telegram и шлёт сообщения |
| `WEBAPP_URL` | https-адрес приложения — для кнопок в сообщениях и кнопки меню бота |
| `ADMIN_TG_IDS` | кому открыт Super Admin и кому приходят заявки |
| `INTERNAL_TOKEN` | пароль бота к серверу; на одной машине создаётся сам |
| `DATA_DIR` | где лежит `zapis.db`; по умолчанию `.run/` |
| `PAYMENT_NOTE` | как платить за подписку — видит владелец |
| `AI_PROVIDER_KEY` | ключ Claude API для AI-помощника; без него AI в демо-режиме |
| `DEV_AUTH` | вход без Telegram для разработки; в бою `false` |

## Проверка

```bash
python -m unittest discover -s server/tests -v   # права, слоты, приглашения, очередь
python -m unittest discover -s bot/tests -v      # бот против заглушки Telegram и живого сервера
```

Экраны приложения проверяются в браузере — порядок описан в `CLAUDE.md`.
Резервная копия — это один файл `zapis.db` в `DATA_DIR`; копируйте его
по расписанию, сервер пишет базу в режиме WAL и копирование на ходу
безопасно через `sqlite3 zapis.db ".backup copy.db"`.

---

## Доступ к Super Admin

В серверном режиме панель открыта тем, чей Telegram ID есть в
`ADMIN_TG_IDS`, — сервер проверяет это на каждом запросе. Команда `/admin`
в боте показывает ваш ID и кнопку панели. В демо-режиме панель открыта
свободно (`DEMO_OPEN_ADMIN` в `webapp/js/config.js`) — это намеренно, для
показа.

## Production-backend (`backend/`)

Отдельный контур на FastAPI и PostgreSQL по `TZ_PRODUCTION.md`: схема
из 43 таблиц, серверный slot engine, очередь с retry, 72 теста. К работе
приложения и бота он не подключён — это задел под масштабирование, см.
`backend/README.md`. Всё, что описано выше, работает без него.
