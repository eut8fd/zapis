# Zapis — состояние проекта

SaaS онлайн-записи в Telegram: Mini App + бот + сервер.
Документ отвечает на три вопроса: **что работает**, **как устроено**
и **что осталось**.

Обновлено: 2 октября 2026.

---

## 1. Что это сейчас

Рабочий продукт, который можно давать людям: данные живут на сервере,
клиент и владелец на разных телефонах видят одно и то же, уведомления
уходят в Telegram по-настоящему, права проверяются сервером.

Версия 3.0. До неё (2.0) приложение было демо на `localStorage`: у каждого
устройства своя копия базы, а общий склад был JSON-файлом, который любое
устройство перезаписывало целиком. Этот режим остался как демонстрационный —
он включается сам, когда сервера нет.

### Архитектура

```
server/
  serve.py     HTTP: статика webapp/, API v2, внутренние маршруты бота, прокси AI
  db.py        SQLite: сущности с порядковым номером изменения, пользователи, очередь
  access.py    роли и права: что видно, что можно писать, какие поля защищены
  slots.py     расчёт свободного времени — порт slotsFor/slotFree из store.js
  notify.py    уведомления: правила, тексты, поток отправки через Bot API
  auth.py      проверка подписи Telegram initData, вход для разработки
  config.py    .env и переменные окружения
bot/
  bot.py       меню клиента и бизнеса, запись в чате, кабинет, очередь
  api.py       клиент к внутреннему API сервера
webapp/js/
  api.js       HTTP-клиент с заголовком initData
  sync.js      серверный режим: загрузка состояния, разница после каждого
               сохранения, приём чужих изменений, неотправленное между запусками
  roles.js     роль человека по членству и привязке к салону
  store.js     состояние, слоты, статистика — как раньше, плюс флаг режима
  screens/     экраны: читают S.data и зовут store, о сервере не знают
backend/       отдельный production-контур на FastAPI (не подключён)
```

### Как данные ходят

Приложение держит своё состояние в `S.data` — массивы компаний, сотрудников,
услуг, записей и т. д. В серверном режиме:

1. при старте `POST /api/v2/boot` с initData → сервер отдаёт состояние,
   уже отфильтрованное по роли (клиент не получает чужих имён и телефонов,
   мастер — денег и отзывов), плюс членство и привязки;
2. любое изменение `S.data` → `save()` → `sync.js` считает разницу со снимком
   и шлёт `POST /api/v2/push`; сервер проверяет права и занятость, пишет
   и возвращает отказы с серверной версией сущности — приложение откатывает
   и показывает причину;
3. чужие изменения приходят `GET /api/v2/changes?since=<seq>` раз в
   полминуты, при возвращении на экран и после каждого push.

Экраны не переписывались: они по-прежнему работают с `S.data`. Переписан
только слой данных — ровно то, что и предсказывал план перехода.

### Роли

Роль не выбирается — она следует из данных:

| кто | как определяется | что видит |
|---|---|---|
| владелец | карточка сотрудника с его telegram-id и `isOwner` | всё по компании |
| администратор салона | карточка с `access: manager` | всё, кроме финансов и отзывов |
| мастер | карточка с `access: staff` | свои записи, свои клиенты; чужие записи — как занятое время |
| клиент | открыл ссылку салона или имеет карточку клиента | публичную страницу, свои записи, свою карточку |
| Super Admin | id в `ADMIN_TG_IDS` | всё |

Запись сервер принимает только если время свободно — та же проверка, что
в приложении, но обойти её нельзя. Цену и длительность записи клиента
сервер считает сам по прайсу.

## 2. Что реализовано

### Клиент
- Запись в Mini App: услуга → мастер → дата (месяц, 4 месяца вперёд) → время
- Запись прямо в чате бота за несколько нажатий — по настоящим окнам
- Мои записи: перенос и отмена, оценка визита после
- Подтверждение «Готово» только после ответа сервера: занятое с другого
  устройства время не превращается в ложную запись
- Уведомления: за 24 часа, за 2 часа, просьба об отзыве, отмена и перенос салоном
- Страница салона: обложка, логотип, услуги с фото, мастера с ближайшим окном
- Закрытый салон (подписка истекла) честно пишет, что онлайн-запись не принимает

### Владелец, администратор, мастер
- Онбординг: три шага, компания создаётся на сервере, владелец получает
  14 дней пробного периода, часовой пояс берётся с устройства
- Календарь: день / неделя / месяц / период, блокировки, отсутствия
- Клиенты, услуги с категориями, команда с ролями и графиками, часы салона
- Приглашение в команду одноразовой ссылкой — с любого устройства
- Финансы, аналитика, отзывы, обучение, поддержка — как в демо
- Уведомления в приложении (колокольчик): новая запись, отмена, перенос,
  вход сотрудника, ответ поддержки, блокировка
- Рассылки клиентам — настоящие, через бота
- Настройки напоминаний живут в компании и управляют сервером
- Подписка: заявка на оплату вместо фиктивного платежа; реквизиты из `PAYMENT_NOTE`
- Несколько компаний у одного человека — переключатель в настройках
- Владелец смотрит свою страницу «глазами клиента» и возвращается в кабинет
  из профиля

### Super Admin
- Всё, что было: компании, тарифы, обращения, журнал, ошибки, люди, блокировки
- Рассылки владельцам — настоящие
- Заявки на оплату, жалобы и новые компании приходят в Telegram
- Состояние сервера: бот, адрес, очередь, недоставленные, размер базы
- Панель администратора в приложении: открыть любую компанию как владелец,
  тестовое сообщение себе, загрузка демо-компаний на пустой сервер

### Бот
- Меню клиента по ссылке салона, быстрая запись в чате, мои записи, отмена
- Меню бизнеса по членству с сервера: кабинет, календарь, ссылка для
  клиентов, очередь уведомлений, смена компании
- Без сервера честно говорит, что сервер недоступен, а не показывает выдуманные окна

### AI-помощник
Режим DEMO считает по данным локально. Режим LIVE в серверном режиме ходит
через сервер (`AI_PROVIDER_KEY`), ключ в браузер не попадает; в демо — по
ключу из браузера, как раньше.

## 3. Что сейчас честно ограничено

| Что | Как сейчас |
|---|---|
| Оплата подписки | по заявке: администратор продлевает вручную после оплаты |
| Фотографии | хранятся в базе как data-URL после сжатия (640px); для сотен салонов нужно файловое хранилище |
| Открытия рассылок | Telegram не сообщает об открытиях: в карточке рассылки только «получили» |
| Конфликты правок | один владелец с двух устройств: побеждает последнее сохранение сущности |
| Часовой пояс | у компании свой (с устройства владельца); приложение показывает время по часам устройства |
| Переводы | клиентская часть и витрина — на трёх языках, кабинет владельца — по-русски |
| Голосовая заметка | распознавание речи не подключено: текст вводится руками |

## 5. Как проверялось

- `python -m unittest discover -s server/tests` — 15 тестов: подпись initData,
  права по ролям, двойная запись, приглашения, очередь, отправка, сводка;
- `python -m unittest discover -s bot/tests` — 8 тестов: бот против заглушки
  Telegram и живого сервера, от /start до отмены записи;
- сквозной сценарий в Chromium: владелец создаёт компанию → клиент
  записывается по ссылке → владелец видит запись и уведомление → мастер
  входит по приглашению → администратор открывает панель; все экраны во всех
  ролях и языках отрисовываются без ошибок и в демо-, и в серверном режиме.

## 6. Как запускать

```bash
python server/serve.py 8080          # сервер
python bot/bot.py                    # бот
powershell -ExecutionPolicy Bypass -File scripts\start-demo.ps1   # всё разом с туннелем (Windows)
```

Публикация — `README.md`: Fly.io (один контейнер), Docker на своём сервере,
systemd. Mini App на GitHub Pages обновляется при каждом пуше в `main`.
